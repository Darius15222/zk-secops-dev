# Audit 2026-11: zk-secops lab

Three rounds of audit, fix and re-audit over the workspace and the three repositories (about 4 400 lines), 2026-11-20 to 2026-11-21. Each round ran three read-only auditors in parallel (security, correctness, maintainability and docs). Every finding was checked against the code, and reproduced where possible, before it was fixed or rejected. Bugs got a test that fails on the old code.

Severity: **blocking** = exploitable or broken; **critical** = real risk or a bug with impact; **warning** = maintainability, readability, docs.

## Result

| Round | Blocking found | Fixed in |
|---|---|---|
| 1 | account takeover across login methods | zk-auth #14, zk-platform #20, zk-detections #11, workspace #15/#16 |
| 2 | sandbox escape through git hooks and the excluded commands | zk-auth #15, zk-platform #22, zk-detections #12, workspace #16 (second commit) |
| 3 | workspace `.git` writable; gitignored files loaded by the user's `make` | branches `audit/r3-*` in all four repositories |

Duplicates between auditors are merged in the tables below. Each table lists every blocking and critical finding and groups the warnings.

After round 3 no blocking or critical finding is open. Round 3 was the last round, so its fixes were verified by tests and probes, not by a fourth audit:
- zk-auth `npm test`: 13/13. The new test fails on the old code.
- `scripts/claude-lockdown.sh`: 42 ok.
- `scripts/claude-sandbox-probe.sh`: 24/24.
- red-team guard: 68/71, 0 missed.
- the CI override check passes on the repository and fails on an `override.tf`.

The main finding of the audit is one class seen three times. The Claude Code sandbox protects only what runs inside it, and the user runs some commands outside it. Each time, the gap was something the assistant could write inside the sandbox that those outside commands then ran or read, without it showing in a diff:
- round 1: options of the commands that were excluded from the sandbox;
- round 2: the excluded commands themselves, and git hooks, config and `commondir`;
- round 3: the workspace `.git` and the gitignored files that `make` loads.

A denylist in `guard.sh` kept failing to close it. The class is now closed by design:
- no command is excluded from the sandbox;
- every `.git` is read-only inside it;
- lab commands run from a separate clone that only receives merged code (`CLAUDE.md`, Sandbox).

## Open (deferred, not blocking)

- Fiat-Shamir domain tag in the Schnorr challenge. Needs a coordinated client and server change.
- In-cluster signature verification (sigstore policy-controller or Kyverno), so `make up` checks the image too, not only CI.
- Per-client cap on outstanding nonces; cap on live lockout keys (both marked `ponytail:` in `server.ts`).
- floci listens on all interfaces. It is shared with other projects, so it was not changed.
- `guard.sh` regex readability (M2-14). The rules are now a second layer.
- Detections contract test across repositories (round 1 C4); an alert rule for `unknown_nonce` (S11); digest drift check; Terraform variable files (M16); registry naming (M25).
- inject-scan.sh misses 16 of 16 disguised injections and flags 6 benign texts (R-06 evidence). The sandbox, not the scanner, is the control.
- zk-detections Dependabot alert #1 (diskcache in `requirements-sigma.txt`): no patched version, used only at build time; left open.
