## triage report

Incident 1: password guessing against user "victim"
- What happened: 50 failed password logins for one user (reason invalid_password: 50, users.victim: 51) in two bursts
  about three minutes apart. The Suricata login burst alerts cover the same minutes from the network side.
- Verdict: attack. One user, 50 wrong passwords, no gap a person would leave. It did not succeed: successful_logins
  has no entry for victim.
- Severity: high, as the rule says. Not raised, because no success follows the failures.
- MITRE: T1110 (brute force).
- Next step (RUNBOOKS.md, brute force, "No success"): nothing to contain; record the source.
- Could not check: the source. 10.42.0.1 is the k3d node address shared by all traffic, so it does not identify a client.
  The five brute force alerts are one incident counted again as the five-minute window slides, not five attacks.

Incident 2: proof replay, users attack7746 and attack30911
- What happened: each user logged in once with a valid proof (successful_logins: 1 each), then the same nonce was
  submitted again (reason nonce_reuse: 2). Both replays were rejected.
- Verdict: unclear between attack and client retry. The original and the replay come from the same source address,
  which the runbook reads as a retry; but that address is the shared node address, so "same source" proves nothing here.
- Severity: high kept. A captured proof being replayed means something on the path can read traffic.
- MITRE: T1550.
- Next step (RUNBOOKS.md, proof replay): compare the timing of the success and the replay per user in Discover.

Incident 3: forged proof, same two users
- What happened: one login per user with a fresh nonce failed verification (reason invalid_proof: 2), seconds after the replay.
- Verdict: attack, as part of incident 2: the same users, the same minute, a replay followed by a proof made with another
  key is one actor probing the zero-knowledge login. One per user, not a stream.
- Severity: medium, as the rule says.
- MITRE: T1110.
- Next step (RUNBOOKS.md, forged proof): none beyond incident 2; the lockout caps further attempts at ten per window.
