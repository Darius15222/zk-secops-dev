# R-06 Bash sandbox evidence, 2026-11-20

Claude Code runs every Bash command in a bubblewrap sandbox (.claude/settings.json, sandbox block; strictAllowlist and
the domain list in the user settings, the only scope that accepts strictAllowlist). Denied paths are masked by the kernel,
writes outside the project and into .claude/ and docs/kb/ fail, network goes through a proxy that only lets the allowlist out.
make, terraform, docker, k3d, kubectl, gh and git push/pull/fetch run outside the sandbox (they need localhost, the docker
socket, the cluster config or the keyring); guard.sh keeps its secret-path text rule for exactly those commands.

Limits found while proving it:
- on Linux the sandbox masks the denied paths that exist when a command starts; a file created by that same command is
  readable (secrets exist beforehand, so the probe creates its canaries in a first run);
- without strictAllowlist, auto mode let example.com and pastebin.com through; with it, the project's allowedDomains
  were ignored until the list was also set in the user settings;
- a cd, a pipe or a redirection keeps an excluded command inside the sandbox (gh then fails with 401), as documented;
- environment variables are visible inside the sandbox; env dumps stay on guard.sh.
